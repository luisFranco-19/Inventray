# Plan: Clean unused fields in Supabase database

## Objectives
- Identify columns and tables in Supabase that are not referenced in the codebase.
- Generate SQL migrations to drop those unused columns/tables safely.
- Follow Supabase best‑practice guidelines (use supabase migration CLI, keep backups, run in staging first).

## Steps
1. **Retrieve current schema**
   - Use the Supabase CLI (`supabase db dump`) or query the `information_schema` via the project's Postgres connection to export the full schema to a file (`schema.sql`).
2. **Collect code references**
   - Search the repository for column and table names:
     - `grep -R "SELECT .* FROM <table>"` and similar patterns.
     - Use `grep -R "<column_name>"` for each column.
   - Record which tables/columns appear in the code (including API routes, front‑end queries, serverless functions, and any ORM definitions).
3. **Compare schema vs usage**
   - Write a script (or use a spreadsheet) to list all columns per table from `schema.sql`.
   - Mark columns that have zero references from step 2 as *unused*.
   - Review tables that have no referenced columns – consider them candidates for removal.
4. **Validate before dropping**
   - For each unused column/table, confirm that it is not a foreign‑key target or part of a view/trigger.
   - Run `SELECT COUNT(*) FROM <table> WHERE <unused_column> IS NOT NULL;` to ensure no hidden data reliance.
5. **Create migration files**
   - Use `supabase migration new drop‑unused‑fields` to generate a migration.
   - Add `ALTER TABLE <table> DROP COLUMN <column>;` statements for each unused column.
   - For whole tables, use `DROP TABLE <table>;`.
   - Include comments in the migration noting the reason and date.
6. **Test migration**
   - Apply migration on a local/ staging Supabase instance: `supabase db up`.
   - Run the project's test suite and smoke tests to verify nothing breaks.
7. **Deploy**
   - Push migration to the main Supabase project: `supabase db push`.
   - Monitor logs for any unexpected errors.

## Deliverables
- `schema.sql` containing the current database schema.
- `unused_fields_report.md` listing each unused column/table with justification.
- Supabase migration file(s) that drop the identified fields.
- Updated README section describing how to run the cleanup process.

## Assumptions & Risks
- Assumes column/table names are uniquely identifiable in the codebase (no dynamic string building that hides them).
- Dropping columns is irreversible; ensure backups exist.
- May affect third‑party services that query the DB directly – verify with stakeholders.
